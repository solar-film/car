## Direct writer: หลักฐานใหม่ที่แยกจาก simulator

ตรวจเฉพาะ private candidate ที่เก็บ local อยู่แล้ว ไม่ติดต่อ Production ตรวจ hash ครบ7ไฟล์เทียบ manifest local ที่ deployAllowed:false; code.gs SHA-256 `9377edbaf0f5676c0711fa5de429b7b39e93cd261b3acbbe99ec77af4907fba2` ไม่ได้ยืนยันว่าเท่ากับ deployment สดในวันนี้ ไม่เผยแพร่ source/auth/service/manifest ส่วนตัว

| กรณี | ผล |
|---|---|
| Valid booking + readback รักษา CustID/Lead ID | ผ่าน |
| Retry เดิมขณะ cache ยังอยู่ | ผ่าน; จึงไม่เหมารวมผล public Code.gs ว่า candidate retry ทุกแบบเสีย |
| Invalid token ไม่เปลี่ยนข้อมูล | ผ่าน |
| Lock unavailable ไม่เปลี่ยนข้อมูล | ผ่าน |
| ไม่มี CustID | ไม่ผ่าน: ยัง append |
| CustID ที่ไม่พบ | ไม่ผ่าน: ยัง append |
| Retry หลัง cache eviction | ไม่ผ่าน: ได้ JobID ใหม่/เพิ่มคิว |
| Mutation ID เดิมแต่ payload ต่าง | ไม่ผ่าน: คืน success เดิมแทน conflict |
| Append สำเร็จแต่ readback ไม่ผ่าน แล้ว retry | ไม่ผ่าน: สร้างคิวใหม่แทนกู้รายการเดิม |

Service/storage/auth ของ Google ยังจำลอง; ไม่ใช้ผลนี้รับรอง concurrency/สิทธิ์/TTL/integration จริง ไม่แก้ writer/source snapshot เดิมในการตรวจนี้ ก่อนแก้ candidate writer ต้องตกลง legacy CustID/client mutation policy และ review durable reservation/fingerprint/recovery ตาม specification ไม่เพิ่มคอลัมน์หรือ backfill เอง

1. Google Staging: ต้องอนุมัติ/ยืนยัน spreadsheet/project/deployment/origin/ผู้ดูแลที่แยกจริง ก่อนสร้างหรือเชื่อมต่อ
